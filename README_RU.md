# AI Telegram Assistant

[English version](./README.md)

Мультимодальный Telegram-ассистент, который направляет запрос к подходящей AI-модели или детерминированному инструменту.

Репозиторий является **портфолио-прототипом**. Он показывает интеграцию и оркестрацию компонентов, но не выдаётся за готовый production-сервис.

## Возможности

- LLM-диалог через OpenAI-совместимый endpoint OpenRouter
- строгий и дружелюбный режимы с ограниченной историей диалога
- анализ изображений настраиваемыми моделями Gemini или Nemotron
- локальная транскрибация русской речи через Faster-Whisper
- извлечение текста из PDF, DOCX и TXT с последующим ответом или саммари
- генерация изображений FLUX через Replicate
- детерминированные уравнения, производные и интегралы через SymPy
- чтение веб-страниц, погода и маршрутизация задач
- бесплатные лимиты, состояния подписки, администрирование и напоминания

## Почему проект устроен так

Не каждый запрос нужно напрямую отправлять языковой модели. Математика вычисляется через SymPy, текст документов извлекается отдельными парсерами, речь распознаётся локально, и только затем результат передаётся LLM для объяснения или оформления. Такое поведение проще проверять и расширять.

## Структура

- `handlers/` — команды Telegram и маршрутизация сообщений
- `services/ai_client.py` — LLM-диалог и история
- `services/vision_analyzer.py` — запросы компьютерного зрения
- `services/voice_transcriber.py` — Faster-Whisper
- `services/document_parser.py` — PDF, DOCX и TXT
- `services/math_engine.py` — точная математика
- `services/image_generator.py` — FLUX/Replicate
- `database.py` — пользователи, лимиты и состояния подписки

## Локальный запуск

```powershell
py -m venv .venv
.\.venv\Scripts\Activate.ps1
pip install -r requirements.txt
Copy-Item .env.example .env
python main.py
```

Минимально нужны `TELEGRAM_TOKEN` и `OPENROUTER_API_KEY`. Для дополнительных функций потребуются соответствующие токены и локальные зависимости, перечисленные в `.env.example`.

## Текущие границы

- SQLite, локальное состояние и polling рассчитаны на прототип.
- Кнопки оплаты отражают сценарий подписки; production-провайдер оплаты ещё должен быть подключён и проверен.
- Идентификаторы моделей настраиваются, поскольку доступность у провайдеров меняется.
- Для production дополнительно нужны автоматические тесты, формальные миграции, наблюдаемость и отдельная проверка безопасности.
